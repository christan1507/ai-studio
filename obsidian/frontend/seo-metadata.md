# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO —
name, `tagline`, description, origin URL, Twitter handle, author, theme colour.
The metadata generator, `robots.ts`, `sitemap.ts`, the JSON-LD helper, **and the
generated brand images** all read from it. Configured for **Superconscious**.

`siteConfig.url` comes from `NEXT_PUBLIC_SITE_URL` (see [[environment-variables]]),
falling back to `https://superconscious.ai`. There is no longer an `ogImage`
field — the OG image is generated (see _Brand images_ below).

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import {
  generateMetadata,
  generateViewport,
} from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "…", description: "…" });
export const viewport = generateViewport();
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: a `title` template
  (`%s — Superconscious`), description, OpenGraph, Twitter cards, canonical,
  `manifest`, robots. `metadataBase` is **always set** from `siteConfig.url`, so
  relative URLs (canonical, generated images) resolve to absolute — required by
  social scrapers. It does **not** set `icons` / `openGraph.images` /
  `twitter.images`: those come from the image file conventions below, which Next
  injects automatically.
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there).

Accepted `generateMetadata` options: `title`, `description`, `url`,
`twitterHandle`, `author`, `siteName`.

## Brand images (generated)

Favicon, Apple icon, OG and Twitter images are **generated from the brand star +
copy** — never hand-made binaries (ADR-0020). The star geometry + palette live in
`src/lib/brand.ts`; each route renders it with `next/og`:

| File convention | Route | Output |
|-----------------|-------|--------|
| `app/icon.tsx` | `/icon` | 512² favicon (also the PWA icon) |
| `app/apple-icon.tsx` | `/apple-icon` | 180² Apple touch icon |
| `app/opengraph-image.tsx` | `/opengraph-image` | 1200×630 share card (star + name + tagline) |
| `app/twitter-image.tsx` | `/twitter-image` | re-exports the OG card |
| `app/manifest.ts` | `/manifest.webmanifest` | PWA manifest (icons → `/icon`) |

To restyle the brand imagery, edit `src/lib/brand.ts` (geometry/palette) or the
copy in `siteConfig` — every image updates together. There is no static
`/favicon.ico`; modern browsers use the `<link rel="icon">` PNG from `app/icon.tsx`.

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` → `getSiteStructuredData()` builds an
`Organization` + `WebSite` JSON-LD graph. The root layout renders it once in a
`<script type="application/ld+json">`.

## Bot detection

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Static assets

The legacy static favicon/PWA set (`favicon-*`, `android-icon-*`,
`apple-icon-180x180.png`, `manifest.json`, `browserconfig.xml`, `open-graph.png`)
has been **removed** — all of it is now generated (see _Brand images_). The
`public/` **root** holds no SEO binaries. Site **content** assets (images,
videos) live under `public/assets/<section>/` — see [[folder-structure]].
